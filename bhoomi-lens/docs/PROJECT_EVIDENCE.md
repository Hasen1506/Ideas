# Official project timeline pilot

The Projects panel includes a small manually reviewed set of infrastructure reports from the Press Information Bureau (PIB), Government of India, for Tamil Nadu and Maharashtra. These examples are neither a complete project register nor a live feed. Each item links to its original source; the archive was reviewed on 13 November 2026. Some recent original pages returned HTTP 403 to the development environment and were read through indexed copies of PIB's own text; their source bytes were not saved or hashed. PIB's [copyright policy](https://www.pib.gov.in/content/102_2_Copyright-Policy.aspx?lang=1&reg=30) permits accurate reproduction with attribution for its material, but excludes third-party content. The app contains factual summaries and links, not embedded photos or third-party content.

The data file is `data/project_timelines.js`. A publication date describes the date on the source, whereas an event date is supplied only when the source specifies it. They are not interchangeable: for example, a 2015 report describes a work stoppage in 2012. An announcement about a planned ceremony is not proof the ceremony happened. The date on a photo album may be the event date rather than its publication date; the publication date is explicitly unknown in that case. A capital cost or financing commitment is not actual expenditure, and an opened section does not imply the whole network opened. Route designs and project definitions can change over time.

The timeline is deliberately separate from the project simulator, map geometry and land-price model. Before any impact study, verify each source and its actual public availability at the forecast origin; exclude records with unknown or later publication dates, resolve project identity and changing routes, collect independent controls, and obtain sufficient compatible, dated land transactions. A small set of official project announcements does not identify a causal land-price effect.

PIB lists an RSS feed but it returned an error when checked on 13 November; several recent pages also returned 403 from this network. The manually dispatched `PIB project source health` workflow makes three bounded read-only checks against an older release, a recent release and the RSS feed; it stores no source data and fails if any response is unavailable or unrecognized.

`scripts/collect_pib_leads.py` can check one public current-month release listing from a network with access. It checks the listing month, declared release count, uniqueness and every row's date before selecting keyword matches. A bad or incomplete response fails without changing the snapshot. With `--apply`, it stores only source headlines, links and publication dates, keeps at most 180 days, deduplicates by PIB release ID, and makes no write if nothing changes. These leads are not fed into the model or map. The list is a lead queue, not a verified project database: keyword matching can miss relevant releases, misclassify unrelated releases and return multiple releases about the same event. A current-month-only source and occasional scans can miss releases around a month boundary. `last_change` is the date the stored list changed, not the date of the latest successful check.

On 13 November the listing was reachable from the development workspace, but a GitHub-hosted test returned HTTP 403; an origin check also found no cross-origin permission for direct browser access. No recurring GitHub collection job is enabled. A durable, permitted network path and another live validation are needed before scheduling collection; the local snapshot alone does not establish continued access.
